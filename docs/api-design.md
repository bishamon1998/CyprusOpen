# Черновик API

Это контракт нашего backend, не поля государственных источников и не работающие endpoints. Уточняем после проверки наборов. API DTO отделены от source DTO и JPA.

| GET | Параметры | Результат |
| --- | --- | --- |
| `/api/v1/statistics/datasets` | — | Статус двух наборов, определение, единицы, география, доступные фильтры, источник |
| `/api/v1/statistics/immigration` | `year` — опубликованный год | Рейтинг по проверенному измерению страны, если такая детализация существует |
| `/api/v1/statistics/tourism` | `year`, `season=all/winter/spring/summer/autumn` | Рейтинг и помесячная разбивка периода |
| `/api/v1/parking` | — | Участвующие парковки; состояние каждой записи |
| `/api/v1/parking/{id}` | Стабильный ID adapter | Одна парковка или 404 |

Годы берём из метаданных, не текущей даты. Сначала полный небольшой рейтинг; универсальные поиск, сортировка и pagination не нужны без реального размера набора.

## Метаинформация

Результат с данными содержит `source` (URL/publisher), `lastUpdatedAt` (наша успешная синхронизация), `lastCheckedAt`, `freshness`, элементы. Времена — ISO 8601 UTC или null до первого события. Для статистики отдельно передаём reference period, metric, unit, geography. Старый год наблюдения сам по себе не означает stale.

`freshness = current | stale | unavailable`. Ошибка последней проверки и свежесть независимы: сохранённая статистика может остаться current после одной ошибки. Порог определяется ожидаемой публикацией и проверенной политикой.

До первого импорта listing возвращает `availability=not_imported`, пустые фильтры и null-времена. После успешного импорта отсутствие строк для разрешённого фильтра — `200`, `items=[]`.

## Периоды и качество

Сезоны — решение продукта: весна Mar–May, лето Jun–Aug, осень Sep–Nov. Зима года Y = Dec Y−1 + Jan Y + Feb Y. Возвращаем `periodStart`, `periodEnd`, число доступных и ожидаемых месяцев. `all` = календарный Jan–Dec года Y; сезонные зимы не являются разбиением этого календарного года.

Рейтинг сезона включает страны с тремя опубликованными значениями; неполные ряды идут отдельно как incomplete, без места в рейтинге. Для полного года нужны 12 месяцев. Подавленные/ненадёжные значения сохраняют quality flag. TOTAL не становится страной; не подгоняем сумму стран под официальный итог при округлениях.

Парковка: `id`, исходное `name`, проверенные `coordinates` или null, `capacity` или null, `availableSpaces` или null, `availability=reported/unknown`, `observedAt` или null, `lastUpdatedAt`, `freshness`. Координаты — отдельные latitude/longitude. Неизвестная доступность не равна 0. Свежесть вычисляется для каждой записи. Время наблюдения может быть старше времени загрузки. При неизвестном времени наблюдения интерфейс показывает только время получения нами и не заявляет измеренную «текущую» доступность.

`stale` — допустимый последний снимок с предупреждением. `unavailable` — нет допустимого снимка, счётчик null. После рестарта коллекция возвращает 200 с `freshness=unavailable` и пустыми items либо известным статическим справочником с null-счётчиками. GET не запускает refresh. До подключения источника не заявляем live-доступность.

## HTTP

| Код | Когда |
| --- | --- |
| 400 | Неверный year/season, год вне опубликованных фильтров, неверный формат ID |
| 404 | Неизвестный dataset или parking ID |
| 503 | Наш сервис не может прочитать своё хранилище; не для обычного отсутствия upstream-снимка |

Ошибка — `application/problem+json`: `type`, `title`, `status`, `detail`, `instance`, стабильный `code`, `requestId`. UI локализует сообщение по code. Без SQL/stack trace. Upstream 429 не транслируем посетителю: используем допустимое последнее состояние.

Сначала `Cache-Control: no-store` для parking и состояния синхронизации: промежуточный кэш не должен скрывать переход в stale. Статистику кэшируем после введения ETag/версии снимка и проверки обновления метаданных. Все запросы браузера к нашим API идут через same-origin proxy.
