# Проект хранения

Это предполагаемые модели, не текущая схема и не утверждение о структуре официальных наборов. В PostgreSQL пока нет доменных таблиц. `database.dbml` продолжает показывать только фактически реализованную схему; новые таблицы появятся вместе с Liquibase.

| Будущая модель Statistics | Назначение | Что проверить до миграции |
| --- | --- | --- |
| Dataset sync state | Код набора, source URL, времена проверки/успеха, status, безопасный error code, validators/checksum | Один источник на набор, политика повторной проверки |
| Immigration observation | Год, исходный код страны предыдущего проживания, значение, quality flag | Существует ли разбивка по странам; прочие измерения и агрегаты; уникальный ключ |
| Tourism monthly observation | Месяц, исходный код страны обычного проживания, arrivals, quality flag | Точная таблица, единицы, коды стран/групп, пропуски, revisions |

Сезонные суммы вычисляем из месяцев; отдельные сезонные таблицы не нужны. Храним исходные коды и подписи; ISO-коды сопоставляем только при проверенном соответствии. Не предполагаем, что все категории — страны. Пропуск хранит причину/quality, не нулевое число. Уникальные ограничения и индексы выбираем по реальным ключам и year/month-фильтрам.

Parking первоначально может работать без таблиц. Если нужен справочник, он хранит только подтверждённые ID, названия, координаты, вместимость и provenance. Счётчики свободных мест, история наблюдений и пользовательская геолокация в PostgreSQL не сохраняются.

Миграции Statistics работают только в схеме `statistics`; при появлении parking-таблиц у них своя схема и история Liquibase. Межсервисных foreign keys и JPA relationships нет. JSONB для переводов используем только при появлении реального multilingual content; статические UI-подписи живут в frontend locale JSON.
